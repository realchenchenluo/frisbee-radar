# 飞盘讯息抓取（frisbee-radar）

把**微信公众号 / 微信视频号 / 小红书 / 抖音**上跟飞盘有关的内容汇总到一处，**只在出现新内容或权威公众号发推送时**产出一份 DOCX 日报，并发布成一个静态网页。

> **网页在线地址**：<https://feipannews.pages.dev/>
> 收录训练/技巧与队伍赛事两类内容，支持按平台、分类筛选和搜索。
> （备用：<https://realchenchenluo.github.io/frisbee-radar/>，同一份内容，两边都在更新）

面向的是「我想知道飞盘圈最近在聊什么」这类需求。两条硬性取舍：

1. **只收两类内容**：训练/技巧优先，队伍与赛事日常次之。媒体报道、行业分析、装备种草、蹭热点的内容**直接不收**——这是白名单，不是排序偏好。见 `config/sources.yaml` 的 `categories`。
2. **事件驱动，不是定时产出**：挂个任务每隔一两小时跑一次，没新东西就直接退出，有新的才生成文档；每条内容只会进一份日报。

四个平台的成熟度差别很大，动手前先看「各平台实测状态」那节——
**公众号免登录就能用；小红书要扫码一次；视频号网页端做不了。**

### 文件放在哪（重要）

沿用「X抓取信息 → 每日X记录」那套布局：


## 一、先说调研结论：GitHub 上有什么

你在动手之前应该知道这块已有的东西，这是实际调研结果（按 star 排序）：

| 项目 | Star | 覆盖平台 | 说明 |
| --- | ---: | --- | --- |
| [NanmiCoder/MediaCrawler](https://github.com/NanmiCoder/MediaCrawler) | 66.2k | 小红书、抖音、快手、B站、微博、贴吧、知乎 | 事实上的标准方案，维护活跃 |
| [chyroc/WechatSogou](https://github.com/chyroc/WechatSogou) | 6.4k | 微信公众号 | 搜狗微信搜索接口封装 |
| [rachelos/we-mp-rss](https://github.com/rachelos/we-mp-rss) | 4.8k | 微信公众号 | 走微信读书路线，生成 RSS，带 Web UI |
| [wnma3mz/wechat_articles_spider](https://github.com/wnma3mz/wechat_articles_spider) | 3.5k | 微信公众号 | 公众平台后台接口，可抓历史文章 |
| [cv-cat/Spider_XHS](https://github.com/cv-cat/Spider_XHS) | 8.0k | 小红书 | 小红书逆向，含私信/直播 |
| [cv-cat/DouYin_Spider](https://github.com/cv-cat/DouYin_Spider) | 3.3k | 抖音 | 抖音逆向，含全量 API |

**结论：通用采集器已经有了，而且很成熟；飞盘垂直方向没有。**

再搜 `frisbee` / `飞盘` 相关仓库，命中的只有几个国外 Ultimate Frisbee 的赛程统计小项目
（`nationals15`、`FrisbeeAPI` 之类），跟国内三平台内容聚合完全不沾边。

所以这个项目的定位是：**不重造通用采集轮子，做一个飞盘垂直的聚合层**。
架构上直接沿用了 MediaCrawler 验证过的核心思路（见下一节），
代价是要自己承担三平台各自的适配细节。

### 为什么没直接套 MediaCrawler

- 它面向「全平台数据采集」，配置和依赖都重（MySQL/Redis/WebUI/词云全套），
  只想每天看一份飞盘简报的话属于杀鸡用牛刀。
- **它不覆盖微信公众号**，而公众号恰恰是飞盘赛事和俱乐部最集中的地方，
  这块必须自己接。
- 它不做垂直领域过滤——飞盘关键词在三个平台都会带回大量噪音，
  这个项目把「相关性打分」当成一等公民来做。

如果你要做的是**大规模、多垂直方向、带 Web 界面**的采集，直接用 MediaCrawler 更划算；
如果你要的是**每天一份飞盘简报**，用这个。

## 二、技术路线

三个平台都有很强的反爬，路线选择是成败关键。

### 采用的方案：浏览器登录态 + 响应拦截

```
Playwright 持久化上下文（登录一次，cookie/localStorage 留在本地）
        │
        ├─ 打开搜索页，让页面自己发请求
        │
        └─ 监听 API 响应（response 事件）→ 直接拿结构化 JSON
```

**为什么不用纯 HTTP + 签名算法**：小红书要 `x-s`/`x-t`，抖音要 `a_bogus`，
这些签名由前端 JS 动态生成且频繁更换。逆向它意味着平台一改版就要重新跟进。
让浏览器自己算签名、自己发请求，我们只在旁边收数据，维护成本低一个数量级。
这正是 MediaCrawler 的核心思路。

代价：需要 Chromium（约 130MB），采集时要跑一个浏览器进程。

### 唯一例外：公众号走搜狗

搜狗微信搜索是纯 HTTP 的，不需要登录，也没有签名。所以公众号的默认模式
（`mode: sogou`）开箱即用；需要抓指定公众号完整历史时才切到 `mode: mp`
（扫码登录公众平台后台，有限流风险，见下文）。

### 各平台实测状态

| 平台 | 状态 |
| --- | --- |
| 微信公众号 | ✅ **已联网实测**：5 个关键词采到 146 条；翻页正常；跳转链接还原为真实文章地址；跨运行去重正确。**免登录，现在就能用** |
| 内容分类与取舍 | ✅ **已在真实数据上核对**：146 条 → 收录 90 条（训练 54 / 队伍 36）、剔除 56 条媒体评论。逐条看过标题，误判已用 `exclude` 修掉 |
| 增量报送 + DOCX 日报 | ✅ **已端到端实测**：16 页日报，格式检查 9/9 通过，逐页渲染核对过排版 |
| 微信公众号后台 `mp` | ⚠️ 代码完成，未实测（需要你名下有公众号，扫码登录） |
| 小红书 | ⚠️ 代码完成，未实测（需要扫码登录） |
| 抖音 | ⚠️ 代码完成，未实测（需要扫码登录） |
| 微信视频号 | ⚠️ **代码完成，未实测，且前置条件最不确定** —— 见下一节 |

需要扫码的三个我都没法代跑——它们必须用**你自己的账号**登录，
我不应该也不方便拿别人的账号去跑。登录后如果接口有变化，见文末「排障」。

### 视频号为什么单独说

这个平台和另外三个完全不是一回事，我实测后确认了三点：

1. **不扫码就什么都不给。** 打开 `channels.weixin.qq.com/web/pages/home`，
   未登录时页面只剩一个转圈的加载指示器，body 里**一个字都没有**，
   内容 API 完全不触发。所以登录是硬前置，没有免登录的取巧办法。
2. **它没有公开的内容搜索接口。** 页面 JS 是 blob 加载的，拿不到源码做静态分析；
   GitHub 上的视频号项目分两类——下载器（挂微信 PC 客户端或浏览器插件，
   抓的是视频文件不是元数据），或者走付费第三方 API（比如
   [wechat-video-collect](https://github.com/shengplus-2024/wechat-video-collect)
   里就是 `axios.post(config.apiUrl)`，而 config 不在仓库里）。
   没有 MediaCrawler 那种可参考的元数据采集实现。
3. **视频号 URL 不稳定**，同一个视频在不同入口拿到的链接形态不同。

所以视频号采集器**不去猜接口**，改用「响应特征匹配 + 通用 JSON 遍历」：
监听所有响应，凡 URL 带 `search`/`object`/`feed`/`finder` 的就取 JSON，
再递归找「长得像视频卡片」的对象，优先认 `objectDesc` 这个包装字段。
好处是即使它改路径或字段名也还有机会抓到；代价是字段可能取不全。

**不确定的部分怎么解决**：登录后跑一次诊断命令，它会把真实请求到的接口
和响应全部落盘，并告诉你哪个接口能提出内容、字段叫什么：

```bash
python run.py login --platform wechat_channels    # 或双击 5-登录视频号.bat
python run.py probe --platform wechat_channels --keyword 飞盘
```

输出在 `data\probe\`。**把这个结果发我，就能把地址和字段对齐。**
这也是我把视频号默认设成 `enabled: false` 的原因——扫码验证过再打开，
否则每次采集都会在它这里报错。

### 一个实测踩到的坑：搜狗已经没有时间筛选了

实采 60 篇文章的发布时间分布是这样的：

```
2016: 3   2018: 2   2020: 2   2021: 3   2022: 32   2023: 17   2025: 1
```

绝大多数是 2022 年飞盘爆火期的内容，最新的只到 2025 年——**这很正常，
飞盘的热度峰值就在 2022**。但由此带来两个必须知道的事：

1. 搜狗**已经静默废弃**了时间范围参数 `tsn`。带上它（哪怕是 `tsn=0`，
   本该等价于不传）服务端会返回一个不含结果容器的空页面，表现为
   「一条都抓不到」且不报错。代码里已去掉这个参数，别再自己加回去。
2. 因此**时间筛选只能在本地做**。刚采完就 `report --days 7` 很可能一条都没有，
   不是坏了。先用 `report --days 3650` 把全量倒出来看，
   确认数据没问题之后再按实际需要收窄。

一个真实的例子：库里 60 条记录，`--days 3650` 出 59 条，少的那条是
2016-04-25 发的——查询行为完全正确，只是被时间窗挡住了。

## 三、怎么用

### 日常（双击就行）

| 什么时候 | 双击 |
| --- | --- |
| 想看有没有新的 | `1-生成日报.bat` |
| 第一次用之前（只需一次） | `6-立基线.bat` |
| 要配权威号 | `2-查看账号.bat` 看号名，再改 `config\sources.yaml` |
| 要抓小红书 / 抖音 / 视频号 | `3-登录小红书.bat` / `4-登录抖音.bat` / `5-登录视频号.bat`（各扫一次码） |

「生成日报」会先采集一轮再判断要不要出文档：没新内容就直接结束、不产生文件，
窗口里会写明原因。所以**没有产出是正常结果**，不是出错。

### 第一次跑

```bash
# 1. 建虚拟环境装依赖（只做一次）
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\playwright install chromium

# 2. 离线跑一遍确认环境没问题（不联网、不登录）
.venv\Scripts\python run.py crawl --mock --mock-as wechat
.venv\Scripts\python run.py report --days 30 --db data/mock.db

# 3. 真实采集 —— 公众号免登录，可以直接跑
.venv\Scripts\python run.py crawl --source wechat

# 4. 立基线，然后出第一份日报
.venv\Scripts\python run.py baseline --yes
.venv\Scripts\python run.py watch --force
```

第 4 步也可以直接双击 `6-立基线.bat` 和 `1-生成日报.bat`。

### 要抓另外三个平台

公众号免登录，另外三个都要各扫一次码：

```bash
python run.py login --platform xiaohongshu && python run.py crawl --source xiaohongshu
python run.py login --platform douyin      && python run.py crawl --source douyin
# 视频号先登录再诊断（见「视频号为什么单独说」），确认能抓到内容后再启用
python run.py login --platform wechat_channels
python run.py probe --platform wechat_channels --keyword 飞盘
```

登录后记得把 `config/sources.yaml` 里对应平台的 `enabled` 改成 `true`。

### 什么情况才产出日报

三条任一成立即可（在 `config/sources.yaml` 的 `watch:` 下配）：

| 条件 | 默认 | 说明 |
| --- | --- | --- |
| 权威公众号有新推送 | 开 | 权威号一发就出，不用等其他号凑数 |
| 可收录内容累计 | ≥ 8 条 | 只数能归类的，媒体评论类不计 |
| 距上次日报的间隔 | ≥ 6 小时 | 防止频繁产出 |

权威号那条可以**无视间隔限制**（`authoritative_breaks_interval: true`），
所以「官方号发推送 → 立刻出一份日报」这个链路是通的。

#### 关于公众号链接的时效性（重要）

**公众号的链接是会过期的**，这是搜狗这条路的固有性质，不是 bug：

    搜狗给的跳转地址形如 mp.weixin.qq.com/s?src=11&timestamp=..&signature=..
    签名有时间窗。实测：采后约 4 小时还能打开，两天后就不是文章页了。

本来想存永久链接（`__biz=..&mid=..&idx=..&sn=..`），但**拿不到 `sn`**：
它在 HTML 里是空字符串、由 JS 运行时填；而且用真浏览器打开时
`window.sn` **依然是空的** —— 从搜狗签名链接进来的文章页不设置它。

所以做了三件事：

1. **每次发布前自动检查链接可用性**。判据是实测出来的：
   失效页 HTTP 200 但只有 **5~28 KB**（固定错误页），有效文章约 **3.4 MB**，
   差 100 倍，用普通 HTTP 请求就能判定，不用开浏览器。
   结果按链接缓存，24 小时内查过的不重复查，不白打平台。
2. **卡片上标注「公众号链接有时效性，建议尽早打开」**，让读者知道要趁早。
3. **链接已失效的卡片改成醒目提示**，并把「按标题搜回原文」提为主要按钮。

小红书**不检查**：它的普通 HTTP 请求一律被重定向到登录页，所有链接看起来
都"失效"，这个判据不能用；而小红书链接没发现过期现象，花几十次页面加载
去验一个不会坏的东西不划算。所以标 `unknown`（读者本来也需要登录小红书
才能看笔记）。

**改词表能立刻生效**：相关性本来是采集时算好存库的，所以光改
`config/keywords.yaml` 不会影响已有数据。现在发布前会用当前词表**重新打分**——
实测收益很实在：撞到一篇奇门遁甲文章讲「鸣法飞盘」（术语同名），
往 `negative` 里加个词，重跑发布那条就没了，不用重新采集。

### 发布网页

日常就双击 `8-发布网页.bat`：生成静态网页 → 安全检查 → 提交 → 推送。
推完 1~2 分钟网页自动更新。

**为什么是「本地生成 + 静态托管」而不是一个后端服务**，这是架构上的硬约束：

| 需求 | 说明 |
| --- | --- |
| 要浏览器内核 | 小红书的 `x-s`、抖音的 `a_bogus` 签名由页面 JS 算，纯 HTTP 请求构造不出来 |
| 要登录态 | 小红书搜索必须登录，登录态是浏览器 profile 里的 cookie |
| 机房 IP 会被拦 | GitHub Actions 的 runner 是数据中心 IP，小红书/抖音/搜狗都拦得很凶，定时任务基本跑不通 |

所以抓取只能在你本机跑。而 **GitHub Pages 只能托管静态文件**——
正好匹配：网页永久在线（免费、免登录、别人直接能看），内容由你双击更新。

```
你的电脑                                    GitHub
┌──────────────────────┐                   ┌──────────────────────┐
│ 1-生成日报.bat        │                   │ 仓库                 │
│  采集 → SQLite       │                   │  ├ frisbee_radar/ 代码│
│ 8-发布网页.bat        │   git push        │  ├ docs/ 静态网页     │
│  生成网页 → 推送      │ ────────────────► │  └ tests/            │
└──────────────────────┘                   └──────────┬───────────┘
                                          GitHub Pages（main 分支的 /docs）
                                          https://realchenchenluo.github.io/frisbee-radar/
```

**首次部署（只做一次）**，见「首次部署网页」一节。

**推送前的安全检查**：`data/` 里是各平台的**登录态 cookie**，一旦推到公开仓库
就等于把账号会话公开了（而且就算之后删掉，git 历史里仍然翻得出来）。
所以 `publish --push` 会先做三项检查，任何一项不过就直接拦住不推：

1. `.gitignore` 是否挡住了 `data/browser_state`、`data/frisbee.db` 等路径
2. 暂存区里有没有 `data/` 或 `.db` 文件
3. 有没有 `.env`、`cookies.json` 之类

**网页发布什么内容**：只发标题、作者、时间、互动数、链接和一小段摘要
（≤80 字），**不发全文**。这是刻意的取舍：全文公开转载有版权风险，
而只给标题+摘要+回链是常见的聚合做法，也能给原作者带流量。
页脚写明了来源和删除联系方式。测试里有一条专门守着这个约定。

### 每天 21:00 自动更新

双击 `9-设置每天21点自动更新.bat` 一次，之后就不用手动跑了。
（取消：双击 `10-取消定时任务.bat`。看运行日志：`data\daily.log`。）

它创建的计划任务叫「飞盘讯息每日更新」，每天 21:00 执行 `auto_daily.bat`：

```
21:00 触发
  ├─ 采集各平台新内容
  ├─ 判断要不要出日报 ── 没有新内容 → 不出，直接结束
  ├─ 网页内容有变化吗 ── 没变化 → 不重写、不提交
  └─ 有变化 → 出日报 + 更新网页 + 推送
```

**核心原则：没有新内容就什么都不做。** 具体来说：

| 情况 | 会发生什么 |
| --- | --- |
| 采集到新内容，且到了出日报的条件 | 出 DOCX 日报 + 更新网页 + 推送 |
| 有新内容但没到出日报的条件 | 不出日报；**网页照常更新**（网站是全量索引，日报是增量简报） |
| 一条新内容都没有 | **什么都不做**：不写文件、不刷新「最近更新」、不产生提交 |

第三条是重点。网页和日报里出现的每一条都来自实际采集，采集不到就是没有——
程序**不会**为了让页面"看起来有更新"而改动时间戳或编造内容。实现上靠一个
**内容指纹**：把生成结果里除时间戳以外的部分做哈希，和现有 `data.json`
比对，一致就直接返回，一个字节都不写。测试里有 7 条专门守着这个行为。

顺带说明：这个计划任务只在**你登录 Windows 时**会跑（桌面工具要浏览器，
不登录跑没意义）。如果 21:00 电脑是关机/睡眠状态，那次就跳过了，不会补跑。

#### 当初为什么换掉 github.io

`<用户名>.github.io/<仓库名>` 这个形状是 GitHub Pages 的机制决定的 ——
只要还用它的默认域名，用户名就一定出现在链接里。改仓库名没用（只换后半段），
把仓库命名成 `<用户名>.github.io` 也没用（还是那个用户名）。

于是换成 Cloudflare Pages：免费、永久，而且**要从你的 GitHub 账号授权一次**
（这一步只能你自己点，我替不了），之后全程命令行。

部署走的是**直传**（我把 `docs/` 传上去），不是 Cloudflare 的「Git 集成」
（那个要它自己去拉仓库，得在后台点一堆东西）。直传的好处是全程不碰后台。

需要 Node.js（本机已有）。登录态存在 `%APPDATA%\xdg.config\.wrangler\`，
一次授权长期有效。


#### 想再进一步：绑自己的域名

现在的 `feipannews.pages.dev` 已经不含用户名了。如果你还想要完全自己的域名
（比如 `https://feipan.info/`），命令已经写好了：

```bash
# 1. 先买域名（阿里云/腾讯云/Namecheap，约 ¥30~100/年）
# 2. 去域名商的 DNS 设置加记录：
#      根域名：类型 A，主机记录 @，记录值依次填这 4 个——
#              185.199.108.153 / 185.199.109.153
#              185.199.110.153 / 185.199.111.153
#      子域名：类型 CNAME，主机记录 www，记录值 realchenchenluo.github.io
# 3. 等生效后：
python run.py domain feipan.info

# 想改回去：
python run.py domain --clear
```

**顺序不能反。** GitHub Pages 一旦认了自定义域名，原来的 `github.io` 地址会
301 跳到新域名 —— DNS 没生效就设置，两个地址都会打不开，网站直接下线。
命令会**先确认域名已经指向 GitHub Pages**，没指向就拒绝执行并列出该做的步骤，
一个字节都不动；`--clear` 之前不动 GitHub 的任何配置。

判据是「**有没有指向 GitHub Pages**」，不是「能不能解析」。这个区别很重要：
实测这台机器的路由器在做**域名劫持**（连 `nonexistent.invalid` 这种保留域名都
返回一个 IP），只看"能不能解析"的话任意垃圾域名都会通过检查。所以判据要求
解析结果是指向 `<用户名>.github.io` 的 CNAME、或者 GitHub Pages 那 4 个官方 IP。
测试里有 12 条专门守这个，包括模拟劫持的场景。

#### 为什么不能直接改 GitHub 那边

- 改仓库名没用 —— 用户名还在链接里
- 把仓库命名成 `<用户名>.github.io`（用户主页站点）也没用 —— 还是那个用户名
- 免费二级域名（`xxx.is-a.dev`、`xxx.eu.org`）倒是不含用户名，但要向它们的
  仓库提 PR 等维护者审核，通常几天

### 怎么抓到"最新"的内容（实测结论）

这条踩过坑，值得单独说：**只搜「飞盘」这一个词，抓到的最新内容停在 2023 年**。
因为搜狗对它按相关性排序，返回的几乎全是 2022 年那波媒体评论（「飞盘火了/凉了」），
而教学类内容一条都排不进来。

换成教学导向的关键词之后，内容立刻变新了：

| 关键词 | 抓到的最新时间 |
| --- | --- |
| `飞盘` | 2025-03 |
| `飞盘教学` / `飞盘技巧` / `飞盘训练` | **2026-04** |
| `飞盘俱乐部` | 2023-11 |

所以 `config/sources.yaml` 里的 `wechat.keywords` 把教学类关键词列在最前面。
想再抓新一点的，就往这个列表里加词——**关键词比排序参数管用**，
因为搜狗的时间筛选参数（`tsn`/`ft`）已经被废弃，带上反而返回 0 条。

真正要稳定拿最新推送，只有两条路：公众号切 `mp` 后台模式（需登录），
或者依赖小红书 / 抖音（这两个平台原生支持按时间排序）。


### 配权威公众号

`watch.authoritative` 里填的号名**必须和采集到的 `author` 字段完全一致**，
先跑 `python run.py authors` 看实际的号名再填。

一个实测的坑：sogou 模式下只有**被搜狗收录**的号才能按名字抓到。
实测「全国飞盘运动推广委员会」可以（一页出 8 条），
「中国飞盘联赛」「飞盘世界」不行——搜出来的是媒体报道提到它们，
不是它们自己发的文章。要稳定盯住这类号，只能切 `wechat.mode: mp`（需登录后台）。

### 改时间（想换成别的点）

双击 `9-设置每天21点自动更新.bat` 用的是 `schtasks /sc daily /st 21:00`。
想改成「每天早上 9 点」，用管理员的命令提示符手动建一次：

```powershell
schtasks /create /tn "飞盘讯息每日更新" /sc daily /st 09:00 ^
  /tr "D:\Desktop\飞盘讯息抓取\auto_daily.bat" /f
```

想更频繁（比如每 2 小时），把 `/sc daily /st 21:00` 换成 `/sc hourly /mo 2`。
不过说实话每天一次够了——这套东西本身就是「有新内容才产出」，
跑得勤只是更快发现，不会多出内容。

## 四、配置

### config/sources.yaml —— 采什么

```yaml
wechat:
  enabled: true
  mode: sogou          # sogou=免登录可直跑 | mp=需扫码，可抓指定号历史
  keywords: [飞盘, 极限飞盘, 飞盘联赛, ...]
  accounts: [中国飞盘联赛, 飞盘世界, ...]   # mode=mp 时生效
```

`crawl.limit_per_target` 控制每个关键词/账号抓多少条，
`delay_min/delay_max` 控制请求间隔——**被风控了先调大这两个值**。

### config/sources.yaml —— 收哪些内容（最关键的一段）

日报的取舍和排序完全由 `categories` 决定：

```yaml
categories:
  - key: training
    name: 训练与技巧        # 排第一
    order: 1
    include: [教学, 技巧, 训练, 入门, 反手, 传盘, 战术, 规则, ...]
    exclude: [俱乐部, 战队, 联赛, 高校, 大学, 狗狗, 犬, 边牧, 射击, ...]
  - key: team
    name: 队伍与赛事动态    # 排第二
    order: 2
    include: [俱乐部, 招新, 迎新, 联赛, 省赛, 交流赛, 校队, ...]
    exclude: [为什么, 怎么样, 凉了, 火了, 出圈, 争议, 媛, ...]
```

匹配规则：**先看 `exclude`，命中就整个丢掉，连 `include` 都不看**；再看 `include`；
按 `order` 从小到大，第一个命中的分类胜出。命中不了任何分类的内容不进日报。

`exclude` 是这套东西的关键，缺了它会出两类误判（都是实测踩出来的）：

| 误判 | 为什么会发生 | 靠哪个词挡住 |
| --- | --- | --- |
| 「神秘掷准飞盘俱乐部现身」被归到训练 | 标题有「掷准」 | 训练类的 `exclude: 俱乐部` |
| 「为什么年轻人都不玩飞盘了」被归到队伍动态 | 标题有「飞盘」相关词 | 队伍类的 `exclude: 为什么` |
| 「飞盘训练出一流的狗狗」被当成训练技巧 | 标题有「训练」 | 训练类的 `exclude: 狗狗 / 犬 / 边牧` |
| 「CF手游飞盘射击技巧」被当成训练技巧 | 标题有「技巧」 | 训练类的 `exclude: 射击 / 手游` |

`category_match.body_min_hits` 默认是 **0，即只看标题**。开启正文兜底的话，
新京报那种媒体科普稿会因为正文里出现「教练」「新手」被误收进训练类——
所以默认关掉，精度优先。

### config/keywords.yaml —— 怎么判断相关性

这一层解决的是**「这条内容是不是在说飞盘」**（挡掉硬盘之类的歧义词），
三档词表：`core`（核心词）、`related`（相关词，需有核心词才计分）、
`negative`（负向词，命中直接判无关）。

注意默认 `threshold: 0.5` 等价于「标题必须命中核心词」——标题命中得 0.60，
正文单独命中只有 0.25。要让「正文提到就算」，把 threshold 调到 0.25。

和 `categories` 的分工：keywords 决定**进不进库**，categories 决定**进不进日报**。

### 日报长什么样

排版参考你已有的「X 情报日报」：**不做封面、不做目录**，第一页顶部一个紧凑题头，
然后直接往下读。对一份经常要看的日报来说，整页封面和目录页都是每次都要翻过去的负担。

- 顶部深墨绿题头区块：标题 + 日期 + 各分类条数
- 分类概览表（分类 / 条数 / **最新发布** / 来源账号数）
- `一、训练与技巧（N 条）` → `二、队伍与赛事动态（N 条）`，**组内按发布时间从新到旧**
- 每条内容：编号 + 加粗标题 → 元信息（@来源 · 平台 · 日期 · 互动）→ 摘要 → 「打开原文」
- 条目之间一条极浅的分隔线，长列表不容易串行
- 结尾「本期数据说明」写明：扫了多少条、收录多少条、剔除了多少条、为什么

字体按正式体规范：H1 黑体 16pt / 正文宋体 12pt，行距 1.3 倍、首行缩进 2 字符、
A4 页面、正文页脚有页码。

有几条是踩过坑才定下来的，改 `docx_report.py` 时注意：
表格**只设 `cell.width` 是不够的**，Word/WPS/LibreOffice 都优先读 `w:tblGrid`，
缺了它列宽会被当等分（标题列会挤成三行）；页脚页码的域开关必须写 `arabic`，
写成 `decimal` 会渲染成「1decimal」；引用链接只挂短标签，公众号地址有 200+ 字符。

### 去重口径

两层：`(platform, post_id)` 主键，加上正文指纹（**长度 ≥ 40 字才启用**——
抖音上大量视频文案就只有几个话题标签，短文本指纹会撞车把不同视频当成同一条）。

**跨平台故意不去重**：同一条赛事新闻在公众号和小红书上的互动数据完全不同，该分开看。

「已报送」是第三层标记（`reported_ts`）：进过一份日报的内容不会再进下一份，
这是判断「有没有新东西」的依据。它只影响增量判断，不动数据。
不属于任何分类的内容也会被标成「已处理」，否则它们会永远留在未报送状态、
每次都把 watch 判成「有新内容」。改了分类关键词后想让旧内容重新入选，
删掉 `data/frisbee.db` 重来，或先用 `baseline` 重置标记。

## 六、限制与合规

**务必先读这一节。**

- 本项目只读取**公开可见**的内容，不做登录绕过、不破解验证码、不接触账号密码。
  登录环节是打开官方登录页让你自己扫码。
- 各平台的服务条款通常禁止自动化采集。**个人学习研究**是常见容忍场景，
  商业使用请先走官方渠道（微信开放平台、小红书开放平台等）。
- 请把请求频率控制在人工浏览的量级。默认 3~7 秒一个请求已经偏保守，
  不要为了快调小。公众号 `mp` 模式的接口是**账号级限流**，超了封约 1 小时。
- 采集到的内容版权归原作者。生成物供内部选题参考，不要再分发。

### 已知的功能边界

- **公众号搜狗模式的新鲜度**：搜狗按相关性排序且时间筛选参数已废弃，
  索引对小众主题更新慢。实测只搜「飞盘」最新只到 2025-03，
  换成「飞盘教学/技巧/训练」能拿到 2026-04 的内容——**关键词比排序管用**。
  要真正稳定拿最新推送只能切 `mp` 模式或依赖小红书/抖音/视频号。
- **视频号的三重不确定**：要登录、接口没文档、URL 不稳定。
  采集器用兜底逻辑尽量抓，但**可能抓不到或字段不全**，
  这也是它默认 `enabled: false` 的原因。先用 `probe` 验证再开。
- **分类是关键词白名单，会有边角误判**：靠词表判别「这是教学还是评论」，
  遇到绕开关键词的写法会漏。比如带「狗」「射击」的已按实测补了排除词，
  但不可能穷尽。**误判的直接修法就是往对应分类的 `exclude` 里加词**，
  加完下次采集就生效（已报送的旧内容不会重判，见「去重口径」）。
- **公众号 mp 模式**：`appmsg` 接口限流极严（约 10~15 次请求后就封 1 小时）。
  代码已把间隔拉到 60 秒以上并在检测到限流时立刻停止，请当低频增量同步用，
  一天跑 1~2 次。
- **小红书**：搜索结果是摘要级的（标题 + 描述），笔记正文要点进详情页才拿得到，
  默认不抓。搜索结果页通常滚 10~20 页到底。
- **抖音**：同理，只拿视频描述和互动数据，不下载视频。
- **相关性判定默认要求标题命中核心词**（见 `config/keywords.yaml` 的 threshold 说明），
  所以一篇正文提及飞盘但标题没提的文章会在更早一层就被过滤掉。

## 七、排障

**「搜狗触发了反爬验证」**
调大 `config/sources.yaml` 里的 `delay_min`/`delay_max`，换个网络，或等几小时。
搜狗对单 IP 的容忍度不高。

**「XX 未登录」**
跑 `python run.py login --platform <平台>`。登录态有效期通常是数周到数月。
要换账号就删掉 `data/browser_state/<平台>/` 再登录。

**登录了但还是报未登录**
平台可能改了 cookie 名。改 `frisbee_radar/browser.py` 里的 `AUTH_COOKIES`，
在浏览器 F12 → Application → Cookies 里看真正的会话 cookie 叫什么。

**采集到了 0 条，或者条数明显偏少**
平台改版导致响应 URL 变了。打开 F12 → Network → Fetch/XHR，
搜索时看真正返回列表的接口路径，改 `frisbee_radar/sources/xiaohongshu.py`
的 `SEARCH_API` 或 `douyin.py` 的 `SEARCH_API`。

**筛出来的内容不对**
用 `python run.py crawl --source X --dry-run -v` 看被过滤掉的内容，
然后去 `config/keywords.yaml` 调词表和 threshold。

## 九、测试

```bash
.venv\Scripts\python -m unittest discover -s tests -v
```

103 个离线单测，不联网、不登录。覆盖：

- **相关性打分**：「飞 盘 变 了」这种中文空格强调、英文大小写、负向词硬拦截、
  相关词需与核心词共现、阈值语义
- **内容分类**：训练类优先于队伍类、`exclude` 压过 `include`、
  未归类被丢弃、默认只看标题、全局排除、组内按时间倒序（含无时间内容排最后）
- **视频号提取**：`objectDesc` 包装与扁平结构两种卡片都能提、错误响应不被当成内容、
  缺字段不生成 `None` 字面量、深嵌套递归有界、`raw` 不塞大对象
- **解析工具**：秒/毫秒时间戳、中文数字单位（「1.2万」）
- **两层去重**：同 id 更新、换 id 但正文相同、短文案不参与指纹去重
- **增量报送**：未报送统计、标记录入、基线、重跑采集不会让已报送内容复活、
  老库自动补列
- **DOCX 结构**：单节无封面无目录、题头区块、训练节排在队伍节之前、
  组内时间倒序、媒体内容被排除、`tblGrid` 列宽、页脚域开关不是 `decimal`、
  链接用短标签、无 Markdown 残留

DOCX 的**视觉**校验不在这套测试里——那个靠渲染成图看。本次交付做了这一步：
LibreOffice 转 PDF → 130dpi PNG → 逐页检查，并用规范自带的 `postcheck.py`
跑格式规则，结果 **9/9 通过、0 错误 0 警告**；16 页无空白页、无溢出、无裁切。

复现这个检查（LibreOffice 是渲染校验必需的转换引擎）：

```bash
winget install TheDocumentFoundation.LibreOffice
soffice --headless --convert-to pdf --outdir out "D:\Desktop\每日飞盘记录\2026-10-05_飞盘日报.docx"
```
